Gradiente de los coeficientes a₁,a₂,a₃ del kernel Gabor

Derivación de ∂L/∂aₙ paso a paso — desde la pérdida, por el alpha-blending, hasta las líneas exactas del rasterizer CUDA. Complementa a kernel_gabor_coeficientes_a.html (la idea/plumbing); aquí solo el gradiente.

Fuente: submodules/diff-surfel-rasterization/cuda_rasterizer/{forward,backward}.cu · proyección en train.py:405-413. Fecha 2026-07-24.

1 · Qué se deriva y contra qué

Cada Gaussiana lleva 3 coeficientes entrenables a₁,a₂,a₃ que definen la forma del kernel de opacidad por serie de cosenos. El optimizador necesita ∂L/∂aₙ. Como L solo depende de aₙ a través de la opacidad efectiva α del splat en cada píxel que pinta, la regla de la cadena es:

L (pérdida)→ imagen píxel→ α = opa·K→ K = (f/f₀)β→ f(r) = ½+Σ aₙ cos(...)
∂L/∂aₙ = (∂L/∂α) · (∂α/∂aₙ)

El primer factor ∂L/∂α (llamado dL_dalpha en el código) lo produce el alpha-blending y es común a todos los parámetros del splat (color, opacidad, β, geometría y también aₙ). El segundo factor ∂α/∂aₙ es la parte específica del kernel Gabor — lo que deriva este documento.

2 · El kernel (forward) — lo que hay que derivar

Con ρ = r² la distancia al cuadrado en el marco local del surfel (∈[0,1)) y r = √ρ:

f(r) = ½ + a₁·cos(πr) + a₂·cos(3πr) + a₃·cos(5πr)
f₀ = f(0) = ½ + a₁ + a₂ + a₃   (pico central, porque cos(0)=1)
g = f / f₀   →   K = gβ   →   α = min(0.99, opa·K)

forward.cu:459-478 — float f = 0.5f + a1*cosf(PI_*r) + a2*cosf(3PI_*r) + a3*cosf(5PI_*r); · float f0 = 0.5f + a1 + a2 + a3; · g = f/f0 (NO se topa a 1: se permiten lóbulos g>1) · kernel = powf(g, beta_j).

Introduzcamos las abreviaturas del código: cₙ ≡ cos((2n−1)πr), es decir c₁=cos(πr), c₂=cos(3πr), c₃=cos(5πr). Entonces f = ½ + a₁c₁ + a₂c₂ + a₃c₃.

Valores iniciales de aₙ (con qué forma arranca cada splat)

Con esta init f(r) ≈ 1−r (tent): f(0)=1, f(0.5)=0.5, f(1)=0 → g=f/f₀ reproduce la rampa y el kernel arranca en (1−r)^β. A partir de ahí el gradiente de §3 deforma esa rampa hacia la variedad Gabor (lóbulos/anillos si algún aₙ se vuelve negativo).

3 · La derivada, paso a paso

Trabajamos con el logaritmo porque K es una potencia. En la región no saturada (opa·K < 0.99, donde el min no muerde):

ln α = ln(opa) + β·(ln f − ln f₀)

Derivando respecto de aₙ. Las dos únicas piezas que dependen de aₙ son f y f₀, con derivadas constantes:

∂f/∂aₙ = cₙ   (porque f = ½ + Σₘ aₘcₘ)
∂f₀/∂aₙ = 1   (porque f₀ = ½ + Σₘ aₘ)

Por tanto:

∂(ln α)/∂aₙ = β·( (1/f)·∂f/∂aₙ − (1/f₀)·∂f₀/∂aₙ ) = β·( cₙ/f − 1/f₀ )

Y como ∂α/∂aₙ = α · ∂(ln α)/∂aₙ, el resultado cerrado es:

∂α/∂aₙ  =  α · β · ( cₙ/f − 1/f₀ )

Y el gradiente que se acumula sobre el parámetro (sumado sobre todos los píxeles que el splat toca):

∂L/∂aₙ  =  dL_dalpha · α · β · ( cₙ/f − 1/f₀ )
Chequeo de consistencia con β: el gradiente de β es ∂α/∂β = α·ln(g) (backward.cu:444). Ambos salen de la misma ln α = ln(opa)+β·ln g: β deriva el exponente, aₙ deriva la base g. Encajan.

4 · Interpretación geométrica: cₙ(r) es la "palanca" de cada aₙ

El término dominante cₙ/f dice que la influencia de aₙ sobre la forma a radio r es exactamente cos((2n−1)πr). Cada coeficiente empuja la opacidad en un patrón de frecuencia distinta:

∂f/∂a₁ = c₁ = cos(πr) ∂f/∂a₂ = c₂ = cos(3πr) ∂f/∂a₃ = c₃ = cos(5πr)

a₁ controla la caída suave global (media onda), a₂ mete una ondulación (onda y media) y a₃ una oscilación rápida (dos ondas y media) → responsables de los lóbulos/anillos finos. En r=0 las tres valen +1 (por eso ∂f₀/∂aₙ=1, común a las tres).

5 · El término −1/f₀ y la proyección Σaₙ=½

Nótese que −1/f₀ en ∂α/∂aₙ = α·β·(cₙ/f − 1/f₀) es idéntico para los tres coeficientes (modo común). El modelo exige el invariante Σaₙ = ½ (para que f₀ = ½+½ = 1, pico normalizado), y se mantiene con una proyección post-step en train.py, no dentro del gradiente:

# train.py:405-413  — proyección ortogonal sobre el hiperplano sum(a)=0.5
if gaussians._a.numel() > 0:
    _excess = (gaussians._a.data.sum(dim=1, keepdim=True) - 0.5) / 3.0
    gaussians._a.data.sub_(_excess)   # resta lo mismo a los 3 -> no sesga la forma

La proyección elimina justamente la componente (1,1,1) de cualquier actualización. Como el término −1/f₀ apunta exactamente en esa dirección, se cancela en la trayectoria restringida: sobre la variedad Σaₙ=½ lo que realmente mueve la forma es el término distintivo cₙ/f. Y con Σaₙ=½ se tiene f₀=1 en la práctica (el run1 lo confirmó: sum(a) min=mean=max=0.5000 exacto). El gradiente NO impone la restricción; la proyección sí. Es un esquema de gradiente proyectado, análogo al clamp de _beta que va justo al lado.

6 · La implementación exacta en CUDA

Todo vive en backward.cu. Primero se recomputa el kernel idéntico al forward (líneas 331-341), luego se acumula el gradiente gateado bajo β≥0.1 (mismo gate que β, evita NaN en el régimen low-β — es el FIX #2 del backward):

// backward.cu:462-470  (dentro de if (beta_j >= 0.1f) { ... })
float f_div  = fmaxf(f, 1e-3f);        // piso SOLO en el denominador del gradiente
float inv_f0 = 1.0f / f0_safe;         // 1/f0  (f0_safe = max(f0,1e-6))
float ab     = dL_dalpha * alpha * beta_j;                       //  dL_dalpha · α · β
float grad_a1 = fminf(fmaxf(ab * (c1 / f_div - inv_f0), -50.0f), 50.0f);

atomicAdd(&dL_da[global_id * 3 + 0], grad_a1);   // acumula sobre todos los píxeles

7 · Las tres decisiones numéricas (y por qué)

1El grad de a NO se puede clampar a ±1e-3 como el de β. El grad de β es de escala natural ~1e-4 y su clamp ±1e-3 casi nunca muerde. El de a es O(1)–O(50) (ver §8): clamparlo a 1e-3 lo aplastaría 3 órdenes de magnitud → mataría la señal. Verificado con finite-difference. Por eso el backstop es ±50, no ±1e-3.

2Piso f_div = max(f, 1e-3) SOLO en el denominador del gradiente. El único riesgo de explosión es cₙ/f con f→0 y β<1 (para β≥1, el factor α∝f^β lleva el producto a 0 y lo acota solo). Se controla en el origen subiendo el piso solo aquí; el forward conserva f_safe=1e-6 intacto (no se toca la imagen renderizada).

3Gate β≥0.1. El bloque entero (grad de β y de aₙ) se salta si β<0.1, igual que β, para evitar NaN en el régimen casi-caja. Color, normal y geometría van fuera de este gate.

8 · Ejemplo numérico (con los valores reales del run1)

Splat con a=(0.627, 0.083, −0.210) (las medias del run1, Σa=0.5 → f₀=1), evaluado en r=0.2 y con la β del run1 β≈26:

c₁=cos(0.2π)=+0.809   c₂=cos(0.6π)=−0.309   c₃=cos(1.0π)=−1.000
f = ½ + 0.627·0.809 + 0.083·(−0.309) + (−0.210)·(−1.000) = 1.191  (> f₀=1 → lóbulo)

∂α/∂a₁ = α·26·(0.809/1.191 − 1) = −8.3·α
∂α/∂a₂ = α·26·(−0.309/1.191 − 1) = −32.7·α
∂α/∂a₃ = α·26·(−1.000/1.191 − 1) = −47.8·α  (roza el backstop ±50 si α→1)

Dos lecturas: (a) las magnitudes O(10–50) justifican por qué el clamp ±1e-3 sería absurdo y por qué el backstop es ±50. (b) Con a₃ muy negativo, f=1.191>f₀ en r intermedio, y β=26 amplifica: g^β = 1.191²⁶ ≈ 94× la opacidad del centro → anillo de opacidad gigante. Esto conecta directamente con el diagnóstico del run1 (β en el techo + 92% de splats con lóbulos activos → colapso). El gradiente es correcto; el problema del run1 fue que la optimización cayó en esa cuenca degenerada.
